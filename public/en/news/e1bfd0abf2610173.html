Introduction

This guidance is aimed at system administrators who are responsible for configuring servers or clients within their estate. It explains how to configure TLS securely and transition to post-quantum cryptography (PQC).

Key recommendations

Use the recommended profiles when configuring TLS.

Only TLS 1.3 provides protection against quantum attacks when configured correctly. You can use our recommended TLS 1.3 profiles now.

If you use TLS 1.2, develop a plan to migrate to TLS 1.3 so you can adopt PQC.

Disable TLS 1.1 and TLS 1.0. You must disable all versions of SSL.

You must disable TLS features known to be insecure.

Keep servers and client software up to date. Implementation flaws can introduce vulnerabilities that may be exploited if security updates are not applied promptly.

About TLS

Transport Layer Security (TLS) is a protocol that provides security for digital communications between two parties. When a server and client communicate, well-configured TLS ensures that no third party can eavesdrop or tamper with any message.

Supported versions

TLS 1.3 is the latest version of TLS. It was designed to be more secure than earlier versions and is the only version that will receive new features in future, such as support for PQC.

TLS 1.2 is still considered to provide strong protection against classical attacks when configured with the recommended cryptographic profiles. However, it will not receive new features apart from critical security updates, as outlined in RFC 9851.

If you use TLS 1.2, you should plan to transition to TLS 1.3 as part of your migration to PQC.

Deprecated protocols

The Secure Sockets Layer (SSL) protocol was the predecessor to TLS. All versions of SSL are deprecated and considered insecure. You must not use them.

TLS 1.1 and 1.0 have also been deprecated by the IETF, as outlined in RFC 8996, and should not be used.

The NCSC recommends that government systems do not support deprecated versions of the protocol, and are upgraded to support TLS 1.3 instead.

Post-quantum cryptography in TLS

A cryptographically-relevant quantum computer would threaten the key exchange and digital signature algorithms currently used to secure TLS. The primary mitigation to this risk is to migrate to PQC, in line with the broader NCSC advice on PQC migration.

Post-quantum key exchange in TLS

RFC 10024 standardises three post-quantum/traditional hybrid key agreement mechanisms in TLS 1.3.

SecP256r1MLKEM768

SepP384r1MLKEM1024

X25519MLKEM768

All three are suitable for protecting personal, enterprise and OFFICIAL-tier government information.

These mechanisms combine the post-quantum ML-KEM algorithm with a traditional elliptic curve algorithm. The NCSC recommends using hybrid schemes as an interim measure when migrating to PQC.

The IETF is developing standards for non-hybrid ML-KEM (ML-KEM Post-Quantum Key Agreement for TLS 1.3), which will standardise MLKEM768 and MLKEM1024 as options for TLS. The NCSC considers these algorithms acceptable for use in TLS, and they are already available in many common TLS implementations.

Post-quantum authentication in TLS

At present, the IETF has only standardised post-quantum algorithms for key exchange in TLS. Work is ongoing to standardise post-quantum authentication in TLS and the wider Web PKI, with a number of drafts at different levels of maturity. Organisations operating private PKIs may be able to adopt post-quantum authentication sooner than services relying on the public Web PKI, where standardisation and wider ecosystem adoption are still ongoing.

Once these standards have been finalised, and mature implementations are available in commercial implementations, this guidance will be updated to include recommendations for their use.

Using cryptographically agile deployments, where it is easier to support alternative cryptographic algorithms, will make these and future transitions easier.

TLS 1.3 configuration

TLS 1.3 introduced some major changes. It uses different cipher suite definitions to earlier TLS versions, and has different configuration options. Some implementations separate TLS 1.3 configuration from previous TLS versions. Please consult your implementation documentation to determine how to configure options specific to TLS 1.3.

The recommended profiles include both post-quantum and traditional algorithms to support the transition to PQC. The recommended symmetric cipher suites are unchanged.

The key exchange algorithms included in the recommended profiles are not the only ones the NCSC considers acceptable. All of the post-quantum key exchange algorithms currently specified for use with TLS 1.3 by the IETF offer appropriate protection for personal, enterprise and OFFICIAL-tier government information.
